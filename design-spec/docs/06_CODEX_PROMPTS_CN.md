# 06｜按阶段交给 Codex 的指令（必须逐步做，不要一次性全部实现）

## 使用方法
解压到一个新工作目录（或现有 repo 的 `design-spec/`），把以下 **阶段 0** 直接发给 Codex。每阶段让 Codex 提交实际可运行代码、构建结果、测试日志。只有上一阶段通过验收才进入下一阶段。

### 阶段 0｜读规格并规划
> 阅读 `README_FIRST.md`、`docs/*.md`、`data/*.json` 与 `reference/APPROVED_GAMEPLAY_STYLE.png`。当前项目是《Don't Drop the King!》的游戏设计规格，不是已实现代码。确认目录、任务依赖、数据字段、风险和最小可运行验收。生成 `IMPLEMENTATION_PLAN.md`、`TASKS.md`；不得修改用户已定画风与核心复活规则。确保最低硬性要求：独立国王刚体，UFO 悬浮和惯性，15 关可配置，免费复活 + 免费 checkpoint，独立平台桥接。

### 阶段 1｜纯灰盒可玩原型
> 新建 Phaser 3 + Matter.js + TypeScript + Vite 项目。仅构建 Level 01 的灰盒地形、1 个 UFO 刚体、1 个独立 King 刚体、3 键操作、左右悬浮探针、失衡预警、镜头、重启。**禁止把 King sprite 固定于 UFO**。添加 `?debug=1` 显示碰撞体、质心、地面探针、接触点、风险值、fps 和调试参数。先使用占位几何，不做动画 UI 和广告。完成后 `npm install && npm run dev` 必须可试玩，`npm run build` 必须成功；提供视频/截图或测试记录。

**验收**：静止时国王不随机掉；急刹可滑落；玩家能通过慢行安全通过；无穿模；关卡落点可达。

### 阶段 2｜完整失败/复活/检查点闭环
> 严格实现 `docs/02_PHYSICS_AND_REVIVE_CN.md`：状态机、失败短演出、Royal Rescue（每 run 一次免费）、Checkpoint Retry（永久免费）、Restart Level（免费）、保存 `runId`/已领取拾取/已用救援/检查点等全部关键字段。画出 UI 并保证连续 30 次失败/重试无卡死。Royal Rescue 可将国王从空中吸回 UFO；恢复后 2.5 秒保护，不能穿墙或跳过危险。当前阶段不要接任何真实广告。

**验收**：刷新也不能重置免费救援；checkpoint 不能重复刷币；任何失败最多两次点击回到可玩状态。

### 阶段 3｜真实关卡与复杂地形
> 将 `data/levels.json`、`data/terrain_modules.json` 载入关卡工厂，完成 12 种物理地形模块、15 关固定 seed 配置；先实现 L01–L05，运行 QA 后再扩展 L06–L15。必须包含断崖、跷跷板、移动平台、破桥、磁力脉冲、低矮通道、风区和弹跳蘑菇；预警、恢复区和碰撞调试必须匹配配置。确保零升级情况下全部关卡理论上与实测可通。加入安全、危险、终点停稳等不同区域检测。

**验收**：15 关可选择进入、逐关解锁；每关成功停靠；敌意随机事件不能形成无解地形。

### 阶段 4｜经济与长期留存
> 实现 `data/balance.json`、`docs/04_ECONOMY_AND_RETENTION_CN.md` 的金币、5 条升级线、三星、首次过关奖励、任务和最佳纪录；使用统一存档服务，同时支持 Mock/Local 与平台存档适配。UI 显示可购买升级和前后变化。确保所有金币支付幂等、免费路径可通关、不看广告也能得到足够金币升级。

**验收**：重新进入网页能保留 15 关解锁和钱包；同一金币、奖励不能通过刷新或重试双领。

### 阶段 5｜已批准美术、动作和搞笑事件
> 以 `reference/APPROVED_GAMEPLAY_STYLE.png` 作为唯一美术方向：简单低饱和、深描边、灰蓝/奶油/紫色/酒红，国王是肥胖米色斑点、头部小触角、皇冠、半眯眼，两个绿外星士兵各有两根**长**触角。请使用可替换 sprite/atlas，严禁把整张概念图作为游戏背景。实现 `data/king_events.json` 中 6 个预警事件；装饰动作不改变主刚体结构。添加简短英文搞笑提示与王冠飞出效果；禁用恶心猎奇的身体元素。

**验收**：无素材时占位不报错；换素材不影响物理逻辑；所有事件有预警且能被玩家应对。

### 阶段 6｜多平台 SDK 和广告
> 按 `docs/05_PLATFORM_AND_QA_CN.md` 构建 MockBridge 和三平台 Bridge；先读取最新官方 SDK 文档，**不要猜 SDK 方法名**。广告只有自然间歇插屏和用户自愿奖励。默认不开放广告换复活，尤其不能要求 Playgama 每次死亡看广告；Basic Launch/无广告模式完整可玩。广告触发时暂停物理和游戏时间，失败/取消不中断正常路线。实现平台级构建命令与环境开关。

**验收**：无广告、未填充、错误、取消、完成 4 种返回均正确；rewarded 只能领取一次，游戏不会因 SDK 卡死。

### 阶段 7｜全平台 QA 和交付
> 写自动化单元/集成测试 + 手工验收清单，重点测试 15 关零升级可通、触屏、键盘、低 fps、保存刷新、从各检查点复活、错误广告。打包适用于平台的静态 HTML5 build，并生成 README 解释本地启动、测试、打包、资源许可和所有已知限制。输出 `QA_REPORT.md`，不要声称没有验证过的功能已通过。

## Codex 指令纪律
- 每阶段交付 `git diff` 摘要 + `npm run build` 结果 + 新增文件清单 + 未解决问题。
- 除非有必要，不改变用户确定的游戏名称、UI 主构图、物理规则、免费检查点。
- 设计配置需要变更时，同步更新 JSON、文档和测试，避免代码与策划分叉。
- Codex 不应该自动提交到真实平台/部署，更不应自行启用盈利设置。
